# 目次先行・章ごと執筆のやり方(Step 4 詳細)

note記事の成否は目次(構成)でほぼ決まる。本文を書き始める前に、目次を確定させる。

## 手順

1. **要素の棚卸し**:`evidence-db.md` を見ながら、読者に伝えたいことを1つ1行で箇条書きにし、番号を振る。この段階では順序や章分けは考えない。
2. **スタートとゴールを1行ずつ**:読者が記事を読み始める時点の状態(悩み・疑問・不安)と、読み終えた時点の状態(理解した・行動できる)をそれぞれ1行で書く。
3. **章立て設計**:スタートからゴールまで、上から順に読めば自然に進める道筋になるように章見出しを作る。
   - 章数は4〜8章
   - 1章1テーマ(複数のテーマを1章に詰め込まない)
   - 見出しは疑問形にせず、名詞・動詞で言い切る(例:「✕ 夜泣きはなぜ起きるの?」→「◯ 夜泣きが起きる3つの原因」)
4. **要素の割り当て**:手順1で番号を振った要素を、それぞれ該当する章に割り当てる。どの章にも入らない要素は無理に入れず捨てる。
5. **ユーザーの承認を得る**:本文を書き始める前に、目次案をユーザーに見せて確定させる。ここを飛ばすと、後で4〜8章分書き直すことになりコストが大きい。

`assets/outline-worksheet-template.md` を使ってこのプロセスをファイルに残し、確定したら `outline.md` として保存する。

## 章ごとの執筆

- 目次が確定したら、「第1章書いて」のように1章ずつ生成を依頼してもらう(または明示的に依頼された場合は順に生成する)。
- 一度に記事全体(数万字)を生成しない。後半になるほど質が落ちやすいため、章単位で区切ることで各章の密度を保つ。
- 各章は `evidence-db.md` にある根拠にのみ基づいて書く。データベースにない主張は書かない。
- 各章は `chapters/` 配下に個別ファイルとして保存する(例:`chapters/01-*.md`)。
